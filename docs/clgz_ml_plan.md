# 错了个字 · 手写识别机器学习改进计划

> 制定日期:2026-08-23(游戏当前处于维护期,平台 v2.5.6 起暂时关闭)
> 背景:现行识别算法(`src/game3/handwriting.ts`:包围盒归一化 + 形态学膨胀 + 字形覆盖 cover/stray 阈值判定)本质是**几何规则**,阈值只能在「误伤认真书写」与「放过潦草涂鸦」之间取舍——v1.0.4 收紧误伤粗笔画、v1.0.5 放松即是两次反复。**代码层面继续调参已接近天花板**,故立项:用真人书写数据训练模型,学习「真人在屏幕上写字」的特征,区分 正确答案 / 潦草但正确 / 残缺半字 / 错别字 / 乱画。
> 本文档为构建计划;动工前需用户确认数据采集方式与里程碑 M0。

## 一、目标与非目标

**目标**
1. 提升「正确书写」通过率(尤其笔画粗、结构紧凑、连笔少的认真书写),同时维持对残缺/乱画的拦截;
2. 区分「潦草但结构正确」与「错别字」——前者应得分,后者不应得分;
3. 判定可解释:输出各类别概率/分数,失败时能提示原因(残缺?结构不像?),替代单一 cover/stray;
4. 全流程可回归:换模型/调参前先在固定评测集上跑分,不出现 v1.0.4 式上线后才发现误伤的回归。

**非目标**
- 不做「玩家写的是什么字」的开放式识别(仍只对题库 165 字逐一判别,是**有约束的二分类/多分类**,难度远低于通用手写识别);
- 不改变玩法、计分与排行榜规则;
- 不引入常驻服务器推理(见部署约束)。

## 二、数据方案(整个计划的核心)

### 2.1 数据从哪来

| 来源 | 内容 | 前提 |
|------|------|------|
| **A. 管理员采集页**(首选,零风险) | 后台新增「笔迹采集」页(admin 鉴权):选一个字 → 画框手写 → 自动记录笔画点序列 + 标签(正确/潦草正确/残缺/错字/乱画);ps 与其他管理员每人每字写若干遍,刻意覆盖 快写/慢写/大字/小字/偏左偏右/粗笔画(触屏笔)/鼠标画 | 无隐私问题,**M1 即可开工** |
| B. 玩家自愿贡献(二期可选) | 游戏内结算页增加明示勾选:「愿意匿名贡献本次笔迹帮助改进识别吗?」,勾选后才上传**归一化后的点序列**(不含 IP/昵称/时间戳关联),并标注玩家自评(我写对了/我写的很潦草) | **必须明示同意 + 匿名化**,不得默认上传(手写笔迹属生物特征敏感数据,这是红线) |
| C. 程序增广(辅助) | 对 A/B 数据做弹性形变/小幅旋转平移/笔画粗细仿真/随机丢笔,扩充训练集 | 无 |

### 2.2 数据格式与规模

- 样本 JSON:`{ char: "锥", label: "correct|sloppy_correct|partial|wrong_char|scribble", strokes: [[x,y],…][…], writer: "ps#2", device: "mouse|finger|stylus" }`;
- 归一化存储(与运行时一致:包围盒 → 56×56 网格),原始坐标不落盘;
- 规模预估(首版):165 字 × 每字 ≥25 条 × ≥3 名管理员 ≈ **12000+ 条原始样本**,增广后训练量翻倍;
- 存储:Cloudflare KV 新键 `clgz_ml:samples`(分批追加)或 R2 对象;**数据集不入 git 仓库**(.gitignore),定期导出本地归档;
- 标注规范:五分类定义写成文档(附例图),双人交叉抽检 10% 样本保证一致性。

### 2.3 数据划分铁律

- **按「书写人」划分 train/val/test**(如 ps 的字迹只能整体出现在同一侧),绝不能按样本随机切——否则模型记住个人笔迹,离线指标虚高、线上失效;
- test 集冻结不再改动,每次候选模型/阈值都在其上出报告。

## 三、模型方案(三级递进,逐级验证收益)

### Phase 0 · 数据驱动调参(无 ML,先行)

- 用采集数据把现行 cover/stray 的 ROC 曲线画出来,重新选工作点;可能直接缓解大部分误伤;
- 产出:阈值建议 + 「现行算法在真实数据上的基线准确率」报告(后续所有 ML 方案都要打赢这个基线);
- 成本最低,**M1 数据一到位就做**。

### Phase 1 · 经典机器学习(小数据友好,推荐首版)

- 特征:cover、stray、笔画数、笔画长度分布、墨迹密度、Hu 矩、投影直方图、起收笔位置等 ~30 维(全部可在浏览器 JS 内计算);
- 模型:逻辑回归 / 随机森林(Python scikit-learn 训练);
- **部署**:树模型可直接导出为 JS 常量数组在 `handwriting.ts` 内推断,零依赖、毫秒级、无需服务端——与现有 Cloudflare Pages 架构完全兼容;
- 输出:五分类概率 → 映射回游戏判定(correct/sloppy_correct 通过;partial/wrong_char/scribble 拒绝并给出原因文案)。

### Phase 2 · 轻量 CNN(数据充足后)

- 输入:64×64 双通道位图(墨迹通道 + 模板字形叠加通道),网络 3~4 层卷积 + 池化 + 全连接(PyTorch 训练,<50k 参数);
- **部署**:导出 ONNX,浏览器端 onnxruntime-web(WASM)推理,CPU 单次 <20ms,仍是纯前端方案;备选 Cloudflare Workers AI 自带 ONNX 运行时;
- 预计比 Phase 1 高 3~8 个百分点,但需要更多数据与前端包体积预算(<300KB);

### Phase 3 · 笔画序列模型(远期可选)

- GRU/小型 Transformer 直接吃归一化笔画点序列(在线手写识别文献路线),对连笔最友好;数据需求最大,仅在前两级遇到瓶颈时考虑。

## 四、工程与上线策略

1. **影子模式先行**:新模型与旧算法并行计算,判定仍以旧算法为准,分歧样本进日志(KV 键 `clgz_ml:shadow`)——积累线上证据且零风险;
2. **切换开关**:识别器版本号化(`recognizer: "geo-v1" | "ml-v1"`),后台可一键回退旧算法;
3. **回归门禁**:`scripts/` 新增评测脚本(读取冻结 test 集 → 输出混淆矩阵/各类查准查全),接入发布检查;关键红线指标:**认真书写误拒率 ≤2%**(v1.0.5 教训)、错别字/乱画拦截率 ≥95%;
4. **调试可视化**:扩展控制台 `__clgzSnapshot()`,叠加显示模型各分类概率;
5. 游戏本体仍在维护期——ML 全部工作在后台/脚本侧完成,**不影响关闭状态**;恢复开放时以新版识别器随 clgz 下一个大版本一起上线。

## 五、隐私与安全红线(不可违反)

- 玩家笔迹**必须明示同意才采集**,默认不上传;同意话术与勾选框需用户确认文案;
- 采集内容仅限归一化笔画序列+标签,禁止携带 IP / 昵称 / 设备指纹 / 时间戳等可关联身份的字段;
- 管理员采集页走 admin 会话鉴权;数据导出走审计;
- 训练数据文件一律 gitignore,不进仓库、不进 commit。

## 六、里程碑(供拍板,顺序即依赖)

|------|------|------|------|
| M0 | 用户确认本计划(采集方式/标签体系/红线条款) | 决策定稿 | — |

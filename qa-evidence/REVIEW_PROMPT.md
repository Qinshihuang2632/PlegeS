# QA 证据审图 Prompt(给视觉模型)

> 用法:把本文件内容原样粘贴给视觉模型,并让它访问 `qa-evidence/`、`qa-evidence/prod/`、`qa-evidence/_stale/` 三个文件夹里的全部文件(PNG 截图 + JSON 记录 + 日志 + 报告)。产出用于:判断哪些是有效证据、哪些是重复/无效,给出最终去重与删除建议。**前提:本批文件尚未删除,先审后删。**

---

你是资深 QA 审核员,负责审核「化了个学」游戏(化学物质消除小游戏,类似羊了个羊)的回归测试证据。请逐文件审查以下三个文件夹中的**全部内容**:

- `qa-evidence/` —— 主批次(3 组测试轮次的截图混放 + 多份 JSON/日志/报告)
- `qa-evidence/prod/` —— 生产环境验证批次(截图 + evidence2.json + run.log)
- `qa-evidence/_stale/` —— 已标为过期的旧批次(大概率整体作废,请单独确认)

> 注意:`qa-extreme.mjs` 已移至 `scripts/`,`REVIEW_PROMPT.md` 即本文件——二者**不参与**本次审计。

## 背景:游戏界面长什么样

- 页面 = 顶部标题栏 + 中间**卡牌棋盘**(方块按层堆叠,层号标注,顶层可点)+ 底部**消除槽(tray,8 格)** + 三张道具卡。
- 卡牌正面是化学式文本(如 `Al₂O₃`、`C₆H₆`、`NH₄NO₃`),同层相邻卡牌颜色不同。
- 点击未被遮挡的卡牌 → 卡牌移入底部槽;槽内满 3 张同类 → 消除。

## 审核任务 A — 逐张截图(PNG)

1. **内容真实性**:截图是否为真实游戏画面(有棋盘、卡牌、化学式、槽位)?是否为空窗/报错页/黑屏/重复帧?
2. **前后一致性**:对每一对「点击前/点击后」(如 `R06-点击前…` 与 `R07-点击后…`):
   - 判断点击后**卡牌是否真的从棋盘移入底部槽**(棋盘少一张、槽多一张)?
   - **若两张截图内容完全相同(卡牌布局、槽位、文字、颜色逐像素一致),判定为「疑似无效证据」**——截图工具抓到的是同一帧,无法证明点击生效。
3. **画面状态合理性**:棋盘卡牌数量、层数、被遮挡关系是否符合文件名描述(如"顶层牌 4 张"、"第1层左上")?
4. **跨文件夹比对**:`qa-evidence/` 与 `_stale/`、`prod/` 之间是否存在**内容完全相同的截图**(不同文件名、同画面)?

## 审核任务 B — 非图片文件(JSON / 日志 / 报告)

1. **JSON 记录 ↔ 截图对应**:核对 `evidence2.json`/`evidence.json` 中 `steps` 里的化学式与同批次截图是否一致(如 `evidence2.json` 的 `Fe₂(SO₄)₃` ↔ `R04/R05` 截图;`prod/evidence2.json` 的 `K₂O₂` ↔ `prod/R04/R05`)。
2. **重复判定**:
   - 三份 `evidence2.json` 是同一脚本**不同轮次**的产物,结构相同、内容不同——**不互为重复**,但要判定哪几轮已过时(`_stale/` 大概率随旧批次整体作废;若主批次 `evidence2.json` 内容已覆盖其结论,则 _stale 版可删)。
   - `dom-evidence.json` 与 `shots.log` **内容一致**(仅尾换行差异),属真重复 → 建议只保留命名规范的 `dom-evidence.json`。
   - `qa-report.md` 与 `qa-report.html` 是同一报告的不同格式 → 建议保留可编辑的 `md`,html 冗余(如 md 缺图再另议)。
   - `run.log`(×2)、`shots.log`:运行日志,无长期证据价值 → 默认建议删除,除非截图缺失需日志佐证。
3. **脚本/报告**:`qa-repro.mjs` 是唯一复现脚本,建议保留(可考虑移入 `scripts/`,此为整理建议,不属删除)。

## 输出格式(严格按此结构)

先给总表,Markdown 表格,**一行一个文件,PNG 与非图片文件全部列入**:

```
| 文件路径 | 类型(截图/JSON/日志/报告) | 内容摘要(一句话) | 判定 | 证据价值 | 与哪张/哪个文件重复·备注 |
```

- **判定**:`✅有效` / `🔁重复` / `⚠️疑似无效(前后同帧)` / `🗑可删除(损坏/无关/纯日志)` / `🕓已过时(被新轮次取代)`
- **证据价值**:`A=必须保留` / `B=可保留可删` / `C=建议删除`

再给三份清单:

1. **【建议删除清单】** —— 逐行:`文件路径 | 类型 | 原因 | 是否可从其它文件恢复同类证据`
2. **【建议保留清单】** —— 每个保留文件一句话说明它证明了什么
3. **【去重方案】** —— 按"内容相同的分组"列出:每组挑哪一份作代表、其余删除;跨文件夹重复要指出冗余方;三份 `evidence2.json` 分别给出去留结论

## 判据与红线

- **相同画面/内容**:PNG 指棋盘布局、卡牌内容与位置、槽位状态、文字、界面元素完全一致;JSON 指逐字段一致。可接受的差异:鼠标悬停高亮、时间显示、末尾换行符。有任何实质差异都算"不同"。
- **不要臆测**:看不清化学式就写"看不清",不要猜。
- **`_stale/` 单独给结论**:整批是否作废(与主批次/生产批次重复或被取代),其中有无比主批次更完整的独特证据。
- **只做审阅与建议,不实际删除**;如果无法访问文件/无图像查看能力,请直接说明,不要编造结论。

## 最终交付

输出总表 + 三份清单 + `_stale/` 整批结论 + 一句总结:预计可安全删除多少张 PNG、多少份 JSON/日志/报告、共约多少 MB。
